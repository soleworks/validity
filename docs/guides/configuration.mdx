A configuration of Validity has three things: the [language and the messages](/guides/messages) of the violations,
and the [clock](/guides/time) that says what "now" is. Every validation uses one.

## Once, at startup

`Validity.configure { }` replaces the default configuration, the one every validation uses unless it is given another:

```kotlin
fun main() {
    Validity.configure {
        language = Language.PT_BR
        messages {
            required = "campo obrigatório"
            brazil { cpf = "CPF inválido" }
        }
        clock = Clock.system(ZoneId.of("America/Sao_Paulo"))
    }

    // ... start the application
}
```

`language` picks the [built-in messages](/guides/messages#in-another-language), `messages { }` changes the ones you
want worded otherwise, and `brazil { }` holds the [messages of a country](/guides/messages#messages-of-a-country).

Each call starts from the built-in defaults, so a second call undoes the first. Call it once, before the first
validation.

## For one call

`Validity { }` creates a configuration that starts from the default one and changes only what its block says. Pass it
to `validate`: the default configuration does not change, so other requests keep theirs.

```kotlin
val friendly = Validity {
    messages {
        minLength = "is too short, use at least {min} characters"
        email = "does not look like an email address"
    }
}

User(name = "A", email = "ana@", age = null).validate(friendly).violations
```

| Path | Message | Code |
|---|---|---|
| `name` | is too short, use at least 2 characters | `minLength` |
| `email` | does not look like an email address | `email` |

The codes stay the same whatever the messages say, which is what lets programs ignore them.

Every way to run takes one: `validate(validity)`, `validateBlocking(validity)`, the `OrThrow` versions, and, for a
[`ContextualValidatable`](/guides/context), `validate(context, validity)`. The configuration reaches the nested objects
and elements too.

## One language per request

A server that answers each request in the language of its user passes the language to `validate`, with no
`Validity` to build:

```kotlin
val language = when (acceptLanguage.substringBefore('-')) {
    "es" -> Language.ES
    "pt" -> Language.PT_BR
    else -> Language.EN
}

order.validate(language = language)
```

The other functions that validate take it too. The messages changed with `messages { }` keep their text in every
language.

The clock varies the same way, for a test or for the zone of a user: see
[Fixing the clock](/guides/time#fixing-the-clock).

<Note>
  `Validity { }` builds its configuration when it is created, on top of the default of that moment. Create the ones you
  reuse, such as one per language, after `Validity.configure`, and keep them in a value.
</Note>
