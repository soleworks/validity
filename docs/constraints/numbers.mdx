The constraints of numbers. The range and sign rules work on every number type, `Int`, `Long`, `Short`, `Byte`,
`Double`, `Float`, `BigInteger` and `BigDecimal`, with an argument of the same type.

<NullArguments />

```kotlin PriceTag.kt
data class PriceTag(
    val price: BigDecimal?,
    val discountPercent: Int?,
    val packSize: Int?,
    val stock: Long?
) : Validatable {
    override fun validation() = validation {
        ::price required {
            positive()
            maxDecimalPlaces(2)
        }
        ::discountPercent required { between(min = 0, max = 90) }
        ::packSize required { multipleOf(6) }
        ::stock required { positiveOrZero() }
    }
}
```

Kotlin's unsigned types, `UInt`, `ULong`, `UShort` and `UByte`, have the range constraints too, with arguments written
with the `u` suffix. They cannot be negative, so they have no sign rules:

```kotlin Packet.kt
data class Packet(
    val ttl: UByte?,
    val port: UShort?,
    val sequence: ULong?
) : Validatable {
    override fun validation() = validation {
        ::ttl required { between(min = 1u, max = 64u) }
        ::port required { min(1024u) }
        ::sequence required { min(1uL) }
    }
}
```

## Whole numbers and multiples

### `integer`

`integer()` on `Double`, `Float`, `BigDecimal`

Checks that the number has no fractional part.

Infinity and `NaN` fail.

Trailing zeros do not count, so `2.00` passes.

<ConstraintFacts code="integer" message="must be an integer" change='integer = "…"' />

### `multipleOf`

`multipleOf(factor)` on every number type: `Int`, `Long`, `Short`, `Byte`, `BigInteger`, `BigDecimal`, `Double`, `Float`

Checks that the number is a multiple of `factor`.

The remainder is computed in decimal, so `0.3` is a multiple of `0.1`. Infinity and `NaN` fail.

## Decimal places

### `maxDecimalPlaces`

`maxDecimalPlaces(max)` on `BigDecimal`, `Double`, `Float`

Checks that the number has at most `max` digits after the decimal point.

Trailing zeros do not count, so `1.50` has one decimal place. On `Double` and `Float`, the number is read in decimal, the way it prints. Infinity and `NaN` fail.

<ConstraintFacts code="maxDecimalPlaces" message="must have at most {max} decimal places" change='maxDecimalPlaces = "…"' />

### `decimalPlaces`

`decimalPlaces(count)` on `BigDecimal`

Checks that the number has exactly `count` digits after the decimal point.

Trailing zeros count, so `1.50` has two decimal places, and a whole number has none.

<ConstraintFacts code="decimalPlaces" message="must have exactly {count} decimal places" change='decimalPlaces = "…"' />

### `minDecimalPlaces`

`minDecimalPlaces(min)` on `BigDecimal`

Checks that the number has at least `min` digits after the decimal point.

Trailing zeros count, so `1.50` has two decimal places.

<ConstraintFacts code="minDecimalPlaces" message="must have at least {min} decimal places" change='minDecimalPlaces = "…"' />

<Note>
  `Double` and `Float` are binary, so `0.1 + 0.2` is `0.30000000000000004`. `multipleOf` and `maxDecimalPlaces` on them
  read the number in decimal, the way it prints, so `0.3` is a multiple of `0.1`. For money, prefer `BigDecimal`.
</Note>
