A constraint is a rule a value must pass, called inside the block of a property: `email()`, `minLength(3)`, `cpf()`.
Each one is an extension of `ValidationNode<V>`, so it is offered only where the value has the type it checks: `email()`
on a `String`, `positive()` on a number, `past()` on a date.

```kotlin
::email required { email() }                       // String
::amount required { positive() }                    // BigDecimal
::items required { notEmpty() }                     // List<Item>
::birthDate required { minAge(18) }                 // LocalDate
```

## What every constraint has in common

<AccordionGroup>
  <Accordion title="A code, which is its name" icon="code">
    The violation of `minLength` has the code `minLength`, in every language and every version. Programs branch on the
    code; people read the message.
  </Accordion>
  <Accordion title="A default message you can change" icon="message-square-text">
    Every constraint takes a `message`, which replaces the default for that call: `minLength(3, message = "too
    short")`. The default itself is changed once, in [the messages](/guides/messages). Each section of these pages says
    which message to change.
  </Accordion>
  <Accordion title="A message built from the value" icon="wand-sparkles">
    A constraint that takes an argument has a second form whose message is a function of the value and the argument:
    `minLength(3, message = { min -> "has $length characters, needs $min" })`.
  </Accordion>
  <Accordion title="Null arguments check nothing" icon="circle-slash">
    `max(customer.creditLimit)`, `equalTo(password)` or `postalCode(country)` with a `null` argument skip the check. The
    missing value is reported once, by `required` on its own property, instead of breaking every rule that reads it.
  </Accordion>
  <Accordion title="Placeholders in the message" icon="braces">
    Messages fill `{path}`, `{value}` and the arguments of the constraint by name: `must have at least {min}
    characters`.
  </Accordion>
</AccordionGroup>

## Reading a section

Each constraint on these pages has the same parts:

```text
minLength(min) on String                              the call, and the types it works on
Checks that the string has at least min characters.   what it checks
Code minLength · Message must have at least {min} characters · Change it minLength = "…"
```

**Change it** is the line to write inside `messages { }` to change its default message, for the whole application or
for one call. See [Messages](/guides/messages).
