Validity is four modules on Maven Central, under the group `io.github.soleworks`, released together and always at
the same version, so a project that uses more than one never mixes versions:

| Module | What it adds | Depends on |
|---|---|---|
| `validity-core` | The DSL, the ways to declare rules (`Validatable`, `ContextualValidatable`, `validation`, `validatable`) and every constraint but the phone ones | The Kotlin standard library and kotlinx.coroutines |
| `validity-phone` | [`phone`, `mobilePhone`, `countryCode` and `areaCode`](/constraints/phone), and their messages | `validity-core` and Google's libphonenumber |
| `validity-ktor` | [`ValidityPlugin`](/guides/ktor), which validates the request bodies of a Ktor server and answers every broken rule | `validity-core` and Ktor 3 |
| `validity-spring` | An auto-configuration that [validates the request bodies](/guides/spring) of a Spring Boot application, MVC or WebFlux, and answers every broken rule | `validity-core` and Spring Boot 3.5 |

Most projects need only `validity-core`.

## Packages and imports

| Package | Module | Holds |
|---|---|---|
| `io.github.soleworks.validity` | core | `Validatable`, `ContextualValidatable`, `validation`, `validatable`, `required`, `ifPresent`, `forbidden`, the presence rules, `each`, `valid`, `include`, `ifInstanceOf`, `convert`, `metadata`, `constraint`, `now`, `Validity`, `Validation`, `ValidationNode`, `SelfValidation`, `ValidationResult`, `Violation`, `ValidationException`, `Messages`, `MessagesKey` |
| `io.github.soleworks.validity.constraints` | core | The general constraints, `or`, `and`, `not`, `HashAlgorithm`, `TaxIdType` |
| `io.github.soleworks.validity.constraints.<country>` | core | The constraints of one country and its messages class, such as `cpf` and `BrazilMessages` in `brazil`: one package per country of [Countries](/constraints/countries) |
| `io.github.soleworks.validity.phone` | phone | The phone constraints, `PhoneFormat`, `PhoneMessages` and `Messages.phone` |
| `io.github.soleworks.validity.ktor` | ktor | `ValidityPlugin` and `ValidityPluginConfig` |
| `io.github.soleworks.validity.spring` | spring | `OnInvalid` |

```kotlin
import io.github.soleworks.validity.*                        // Validatable, validation, required, each, ...
import io.github.soleworks.validity.constraints.*            // email, minLength, positive, ...
import io.github.soleworks.validity.constraints.brazil.*     // cpf, cnpj, cep, ...
import io.github.soleworks.validity.phone.*                  // phone, mobilePhone, ... (validity-phone)
import io.github.soleworks.validity.ktor.*                   // ValidityPlugin (validity-ktor)
import io.github.soleworks.validity.spring.*                 // OnInvalid (validity-spring)
```

Your IDE adds them for you when you complete a constraint.

## Why phone numbers are apart

libphonenumber is large and holds the numbering plans of every country. Keeping it out of `validity-core` means a
project that never validates a phone number does not ship it. A module adds its messages to the configuration without
the core knowing it, through `MessagesKey`, the same way [your own constraints](/guides/messages#messages-of-your-own-constraints)
can.

## Versions

Validity follows [Semantic Versioning](https://semver.org). While the version is `0.x`, a breaking change raises the
minor version, so moving to the next minor version may ask you to change your code. The
[changelog](https://github.com/soleworks/validity/blob/main/CHANGELOG.md) says what to change.
